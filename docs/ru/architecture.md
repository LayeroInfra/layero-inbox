# Архитектура

Layero Inbox — три статических фронтенда и одна база. Сервера приложения нет:
вся логика, которую нельзя доверить браузеру, живёт в Postgres.

```
 сайт клиента                      inbox.layero.app            data.layero.ru/<база>
┌──────────────────┐              ┌──────────────────┐        ┌──────────────────────┐
│ <script embed.js>│──iframe──▶   │ widget: frame.html│──RPC──▶│ api.site_form         │
│ кнопка, снимок   │  postMessage │ формы, загрузка   │──PUT──▶│ api.submit_form       │
└──────────────────┘              └──────────────────┘        │ storage: screenshots │
                                                              │                      │
                                  ┌──────────────────┐        │ RLS: sites, reports, │
             владелец, команда ─▶ │ web: /dashboard/ │──REST─▶│ site_members, invites│
                                  │ supabase-js      │──auth─▶│ auth: почта, Яндекс  │
                                  └──────────────────┘        │                      │
                                                              │ триггер → net.http_post
                                                              └──────────┬───────────┘
                                                                         ▼
                                                                 api.telegram.org
```

## Компоненты

| Проект Layero | Папка | Что это |
|---|---|---|
| `<адрес>` | `apps/web` | Vite, две страницы: лендинг `/` и кабинет `/dashboard/`. Кабинет — supabase-js с публичным ключом Data API. |
| `<адрес>-widget` | `apps/widget` | `embed.js` — скрипт для чужих сайтов; `frame.html` — форма, открывается в iframe. |
| база `inbox` | `db/migrations` | Таблицы, RLS, функции `api.*`, политики хранилища, уведомления. |

Оба проекта подключены к базе флагом `--db`: при сборке Layero подставляет
`VITE_LAYERO_DATA_URL` и `VITE_LAYERO_DATA_KEY` (публичный ключ, роль `anon`).
Секретный ключ `service_role` в браузер не попадает и приложению не нужен.

## Почему виджет в iframe

`embed.js` выполняется на чужом домене. Если бы он ходил в Data API сам:

- пришлось бы разрешить CORS для любого источника, а Data API по умолчанию
  принимает запросы только с адресов проекта;
- публичный ключ и вся логика формы оказались бы в контексте чужой страницы,
  где любой скрипт может их перехватить.

Поэтому `embed.js` только рисует кнопку, делает снимок экрана (html2canvas-pro,
он работает только в контексте страницы) и открывает `frame.html` с адреса
виджета. Запросы в базу идут из iframe — с «своего» источника. Связь между
страницей и iframe — `postMessage` с проверкой `origin`:

```
embed.js                         frame.html
   │── открыть iframe ───────────▶│
   │◀──────────── li:ready ───────│
   │── li:init {page_url, снимок}▶│
   │◀──────────── li:close ───────│
```

## Где выполняется логика

| Что | Где | Почему там |
|---|---|---|
| Кто видит сообщения сайта | RLS-политики `reports_read` и др. | Браузеру нельзя доверять фильтр `site_id` |
| Приём формы от посетителя сайта | `api.submit_form`, SECURITY DEFINER | Посетитель не может писать в таблицу напрямую — функция проверяет ключ сайта, форму, согласие, слот, частоту |
| Свободные слоты записи | `inbox_private.free_slots` | Один источник правды для виджета и проверки при записи |
| Двойная запись в слот | уникальный индекс `reports_booking_slot` | Гонку двух посетителей решает база, а не код |
| Кто может загрузить снимок | политика на `storage.objects` | Путь выдаёт `submit_form`, загрузка разрешена 10 минут и один раз |
| Уведомление | триггер `reports_notify` → `net.http_post` | Запрос уходит после коммита, токен бота — секрет базы |
| Приглашения | `api.accept_invites` | Почта берётся из `auth.users`, а не из запроса |

## Схема `api`

Data API публикует функции из схемы `api` по адресу
`POST /rest/v1/rpc/<имя>`. Имена аргументов — публичный контракт: клиент
передаёт JSON с теми же ключами. Внутренние функции лежат в `inbox_private` и
напрямую не вызываются.

`npx layero@latest data methods --db inbox` показывает, какие таблицы и
функции видны каждой роли, и предупреждает об опасных настройках.
